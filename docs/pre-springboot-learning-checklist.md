# Spring Boot導入前 学習到達目標チェックリスト

このチェックリストは、`step1`〜`step5` の学習をコンテンツ化するための到達目標確認用です。  
対象アプリ:
- `step1-greeting-web`
- `step2-todo-lite`
- `step3-kakeibo-lite-web`
- `step4-reservation-form-app`
- `step5-attendance-mini`

## 1. 共通知識チェック

### 1-1. 開発環境・実行
- [ ] `javac -encoding UTF-8 App.java` と `java App` で起動できる
- [ ] 絶対パスで作業ディレクトリへ移動できる
- [ ] 起動中プロセスを `Ctrl + C` で停止できる

### 1-2. HTML / CSS
- [ ] `form` / `input` / `select` / `button` / `table` を使って画面を作れる
- [ ] `display: flex` / `grid` でレイアウトを組める
- [ ] 最低限のレスポンシブ対応（画面幅に応じた調整）ができる

### 1-3. JavaScript（画面制御）
- [ ] `DOMContentLoaded` 後に初期処理を実行できる
- [ ] `addEventListener` でフォーム送信・クリックイベントを扱える
- [ ] DOMを更新して画面を再描画できる
- [ ] 配列の `filter` / `forEach` を使って一覧を表示・絞り込みできる

### 1-4. HTTP / API
- [ ] `GET` / `POST` / `PATCH` / `DELETE` の用途を説明できる
- [ ] `fetch` + `async/await` でAPI通信できる
- [ ] `response.ok` とステータスコードで成功/失敗を分岐できる
- [ ] JSONの送受信（`JSON.stringify`, `response.json()`）ができる

### 1-5. Java（サーバー側）
- [ ] `HttpServer` と `HttpExchange` でAPIエンドポイントを作れる
- [ ] リクエストボディを読み取り、JSONレスポンスを返せる
- [ ] `List` / `record` / `enum` を使ってデータモデルを表現できる
- [ ] `synchronized` で簡単な整合性を確保できる

### 1-6. 業務ロジック・バリデーション
- [ ] 必須チェック・文字数チェック・数値チェックをサーバー側で実装できる
- [ ] エラー時に適切なメッセージを返せる
- [ ] 「UIではなくサーバーでルールを守る」設計を理解している

## 2. ステップ別チェック

### 2-1. step1 Greeting Web
- [ ] 入力した名前をAPIに送り、挨拶文を画面表示できる
- [ ] 空入力時にエラーメッセージ表示ができる
- [ ] 最小構成（画面 + API + 通信）の流れを説明できる

### 2-2. step2 ToDo Lite
- [ ] タスク追加ができる
- [ ] 一覧表示ができる
- [ ] 完了/未完了の切り替えができる
- [ ] 削除（確認ダイアログ付き）ができる
- [ ] 画面リロードなしで一覧更新できる

### 2-3. step3 家計簿Lite Web
- [ ] 収入/支出を登録できる
- [ ] 合計（収入・支出・差引）を表示できる
- [ ] 種別/カテゴリで絞り込みできる
- [ ] 金額や文字数のバリデーションを実装できる

### 2-4. step4 予約フォームアプリ
- [ ] 予約登録ができる（名前・日付・時間帯）
- [ ] 一覧表示とキャンセルができる
- [ ] 時間重複予約をサーバー側で拒否できる
- [ ] 開始/終了時刻の前後関係を検証できる

### 2-5. step5 勤怠ミニ
- [ ] 出勤/退勤の状態遷移を実装できる
- [ ] 本日の状態（未出勤/出勤中/退勤済み）を表示できる
- [ ] 勤怠履歴を一覧表示できる
- [ ] ユーザー一覧の検索・ロール絞り込みができる
- [ ] 削除確認ダイアログを実装できる
- [ ] 履歴があるユーザーの削除禁止ルールを実装できる

## 3. 学習完了判定（Spring Boot導入前）
- [ ] `step1`〜`step5` を自力で起動し、主要機能を再現できる
- [ ] APIエラー時の原因を「画面/通信/サーバー」に切り分けて説明できる
- [ ] 業務ルールをサーバー側に実装する理由を説明できる
- [ ] 次段階（Spring Boot）で何が改善されるかを説明できる

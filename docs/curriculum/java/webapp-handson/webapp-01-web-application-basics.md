## 3. 先に覚えるポイント
1. Webアプリは「ブラウザ」と「サーバー」の通信で動く
2. ブラウザは入力と表示、重い処理は主にサーバーが担当
3. リクエストとレスポンスの往復を1セットとして扱う
4. 動的Webページはサーバー側の処理結果で表示内容が変わる

---

## 4. ハンズオン

目的:
- Webアプリの通信と役割分担を図と言葉で整理する

完了条件:
- 「誰が」「どこで」「何を処理するか」を説明できる

作成ファイル: `~/order-management-springboot/practice/webapp/handson01/webapp-flow.md`

### Step 0: 作業フォルダ作成
```bash
mkdir -p ~/order-management-springboot/practice/webapp/handson01
cd ~/order-management-springboot/practice/webapp/handson01
```

### Step 1: リクエスト/レスポンスの流れを整理
`webapp-flow.md` を次の内容で作成:

```markdown
# Webアプリ通信メモ
1) ブラウザで操作（検索ボタン押下など）
2) ブラウザがHTTPリクエストを送信
3) サーバー側で処理（業務ロジック/DBアクセス）
4) サーバーがHTTPレスポンスを返却
5) ブラウザが結果を表示
```

### Step 2: 役割分担を追記
`webapp-flow.md` に以下を追記:

```markdown
## 役割分担
- クライアント（ブラウザ）: 入力受付、結果表示
- Webサーバー: HTTP受付/返却
- APサーバー: アプリ実行（Servlet/JSP）
- DBサーバー: データ保存/検索
```

### Step 3: 動的/静的ページを分類（仕上げ）
次の2つを比較メモとして追記:
- 静的: 毎回同じHTMLが返る
- 動的: DBや入力値でHTML内容が変わる

## 6. つまずきポイント
- WebサーバーとAPサーバーを同じ役割だと思ってしまう
  -> HTTPの受付とアプリ処理は責務が異なる
- 「画面表示=すべてブラウザ処理」と誤解する
  -> 表示データ生成はサーバー側が担当することが多い

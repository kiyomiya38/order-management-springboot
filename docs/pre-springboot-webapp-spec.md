# Spring Boot導入前 段階学習アプリ仕様書

## 1. 目的
- プログラミング未経験者が、`HTML` / `CSS` / `JavaScript` / `Java` を使ってWebアプリを段階的に作れる状態になること。
- 最終的に、現在の勤怠管理アプリ（Spring Boot版）へ無理なく接続できる基礎を作ること。

## 2. 対象者
- プログラミング未経験者
- Web開発未経験者

## 3. 学習範囲
- 対象:
  - HTMLで画面構造を作る
  - CSSで画面を整える
  - JavaScriptで画面操作（イベント、DOM操作、非同期通信）を行う
  - JavaでWeb APIと業務ロジックを実装する
- 今回は対象外:
  - Spring Boot
  - テストコードの本格導入

## 4. 共通技術方針
- バックエンド:
  - Java（Spring Bootは使わない）
  - Java標準のHTTPサーバー（`com.sun.net.httpserver.HttpServer`）を基本とする
- フロントエンド:
  - HTML / CSS / JavaScript（フレームワークなし）
  - `fetch` でAPI通信
- データ保持:
  - 前半はメモリ保持
  - 後半でファイル保存（任意）または簡易永続化を導入

## 5. 段階学習アプリ（全5本）

### ステップ1: Greeting Web（最小構成）
目的:
- Webアプリの最小構成（画面 + API + 通信）を理解する

必須機能:
- 名前入力フォーム
- 送信ボタン
- Java APIへリクエストし、画面に挨拶メッセージ表示

実装ポイント:
- JavaScriptで `submit` イベントを扱う
- `fetch` で `POST /api/greeting` を呼ぶ
- Java側でJSONを受け取り、JSONを返す

完了条件:
- 入力値を使った挨拶が画面に表示される
- エラー時に簡単なメッセージ表示ができる

### ステップ2: ToDo Lite（CRUD基礎）
目的:
- Webアプリでの作成・参照・更新・削除（CRUD）の基本を学ぶ

必須機能:
- タスク追加
- 一覧表示
- 完了/未完了の切り替え
- タスク削除

実装ポイント:
- Java側でタスク一覧をメモリ保持
- JavaScriptで一覧を再描画
- 削除時の確認ダイアログ（`confirm`）を実装

完了条件:
- 4つのCRUD操作がすべてブラウザ上で完結する
- 画面リロードなしで一覧更新できる

### ステップ3: 家計簿Lite Web（業務ロジック基礎）
目的:
- 入力チェック・集計・絞り込みなど、業務ロジックを実装する

必須機能:
- 収入/支出の登録
- 一覧表示
- 合計金額表示
- カテゴリまたは種別で絞り込み

実装ポイント:
- Java側で金額バリデーション（0以下禁止など）
- JavaScriptで条件絞り込みUI
- フォーム入力エラーを画面に明示

完了条件:
- 不正入力を防ぎつつ登録できる
- 絞り込みで表示件数が変わる
- 合計が正しく更新される

### ステップ4: 予約フォームアプリ（ルール判定）
目的:
- 「業務ルールをサーバー側で守る」実装感覚を身につける

必須機能:
- 予約作成（名前、日付、時間帯）
- 予約一覧
- 予約キャンセル
- 同時間帯の重複予約禁止

実装ポイント:
- Java側で重複判定を実装
- JavaScript側では事前チェックと結果表示を担当
- 成功/失敗メッセージをUIに反映

完了条件:
- 重複予約がサーバー側で拒否される
- 正常時のみ予約が追加される

### ステップ5: 勤怠ミニ（最終アプリへの橋渡し）
目的:
- 最終アプリに近い状態遷移とUI改善を先に体験する

必須機能:
- 出勤
- 退勤
- 状態表示（未出勤/出勤中/退勤済み）
- 履歴一覧表示
- ユーザー一覧の検索・絞り込み（画面遷移なし）
- 削除確認ダイアログ

実装ポイント:
- Java側で状態遷移ルールを厳密に管理
- JavaScriptで検索・絞り込み、削除確認を実装
- `data-*` 属性を使ってテンプレート値をJSで扱う

完了条件:
- 出勤/退勤の不正遷移が防止される
- UI操作性の改善（確認ダイアログ、絞り込み）が実感できる

## 6. 進め方の原則
- 学習順序は必ず `ステップ1 -> ステップ2 -> ステップ3 -> ステップ4 -> ステップ5`
- 各ステップで「必須機能を満たすまで次へ進まない」
- まず動くものを作り、その後に見た目やコード整理を行う
- 詰まった場合は「画面」「JavaScript」「Java API」のどこで止まっているかを分離して確認する

## 7. 最終到達イメージ
- 上記5本を完了した時点で、次の学習（Spring Boot導入）に入る。
- Spring Boot導入後は、同じ機能をフレームワークで再構成し、保守性と拡張性を高める。
